## 1. Hermes Exa backend, from source

- The Exa backend is a bundled plugin: `plugins/web/exa/provider.py` + `plugins/web/exa/plugin.yaml` (`name: web-exa`, `kind: backend`, `provides_web_providers: [exa]`). It uses the `exa-py` SDK, "lazy-installed". RAW/plugins/web/exa/provider.py [verified]
- `web_search` sends exactly: `_get_exa_client().search(query, num_results=limit, contents={"highlights": True})`. No `type`, `category`, date filter, domain filter, `summary`, `text` or `outputSchema` is passed, so Exa's default search type (`auto`) applies. The client also sets header `x-exa-integration: hermes-agent`. RAW/plugins/web/exa/provider.py [verified]
- What the model gets back per hit: `web_hit(r.url or "", r.title or "", " ".join(r.highlights or []), i + 1)`, which is `{"url", "title", "description", "position"}` wrapped as `{"success": True, "data": {"web": [...]}}`. Highlights are joined into one `description` string. `publishedDate`, `author`, `image`, `favicon`, `id` and cost are dropped. RAW/plugins/web/_common.py (`search_ok`, `web_hit`) [verified]
- Tool schema exposed to the model: `web_search(query, limit)` only; "Maximum number of results to return. Defaults to 5", clamped `min(max(int(limit), 1), 100)`. Operators such as `site:domain` are just passed inside the query string. RAW/tools/web_tools.py [verified]
- `web_extract` sends `_get_exa_client().get_contents(urls, text=True)` and returns per page `{"url", "title", "content", "raw_content", "metadata": {"sourceURL", "title"}}`; failed URLs come back as error entries built from Exa `statuses[]`. Schema: `urls` ("max 5 URLs per call") and `char_limit` ("default 15000"; larger pages are head+tail truncated with the full text stored to disk). RAW/plugins/web/exa/provider.py, RAW/tools/web_tools.py [verified]
- No hook for Exa-specific options: the provider interface is `search(self, query: str, limit: int = 5)` and `extract(self, urls: list[str], **kwargs)` (kwargs are only `format`, `include_raw`, `max_chars`). RAW/agent/web_search_provider.py [verified]
- Config: `web.backend: "exa"`, or per capability `web.search_backend` / `web.extract_backend`; `EXA_API_KEY` in `~/.hermes/.env`. Without a key Exa is a member of the "keyless free-tier ring" (round-robin over Exa, Parallel, Firecrawl, Keenable), so set the key and pin the backend or searches may silently go to another vendor. RAW/website/docs/user-guide/features/web-search.md [verified]
- Search responses are memoised (`tools/web_result_cache.py`, `search_memo`), so a repeated identical query may be served from cache. RAW/tools/web_tools.py [verified]
- Conclusion (fact-based): the built-in backend gives the model URL + title + highlight snippet, enough for inline links but with no published date, no author, no structured citations, no filters and no deep/structured search. For sources shown in a UI, date/domain/category filters, `outputSchema`, `/answer` citations, Monitors or Agent runs, use Exa's hosted MCP server (`mcp_servers:`) or a custom plugin tool (section 2).

## 2. Hermes custom tools, plugins, skills, repo-local config

### Custom tool = plugin
- Docs say to use a plugin, not a core tool: "If you want a personal, project-local, or otherwise custom tool without modifying Hermes core, use the plugin route instead". RAW/website/docs/developer-guide/adding-tools.md [verified]
- Layout: `~/.hermes/plugins/<name>/plugin.yaml` + `~/.hermes/plugins/<name>/__init__.py`. Manifest keys in the example: `name`, `version`, `description`, `provides_tools: [...]`, `provides_hooks: [...]`; `requires_env: [API_KEY]` gates on env vars. RAW/website/docs/user-guide/features/plugins.md [verified]
- Registration API: `def register(ctx):` then `ctx.register_tool(name="hello_world", toolset="hello_world", schema=schema, handler=handle_hello)`; schema is `{"name", "description", "parameters": {JSON schema}}`; handler signature `handle(params, **kwargs)` and it returns a JSON string (`json.dumps({...})`). Hooks: `ctx.register_hook("post_tool_call", fn)`. Same doc [verified]
- Tool rules (core-tool doc, same contract): "Handlers **MUST** return a JSON string", "Errors **MUST** be returned as `{"error": "message"}`, never raised"; async handlers via `is_async=True`. RAW/website/docs/developer-guide/adding-tools.md [verified]
- Enabling: "General plugins and user-installed backends are disabled by default" until the name is in `plugins.enabled` in `config.yaml`; `hermes plugins enable <name>`. Toolset: "With no saved selection the lists are left alone: a plugin's toolset is on by default"; if `hermes tools` saved a selection (`platform_toolsets`), enabling the plugin puts its toolset back. Restart Hermes after dropping files in. plugins.md [verified]
- Project-local plugins do not work: "The gateway does not load project-local plugins ... Setting `HERMES_ENABLE_PROJECT_PLUGINS=true` therefore has no effect on sessions". "To use a plugin, install it as a user plugin (`~/.hermes/plugins/` or `hermes plugins install`)". Other distribution routes: `hermes plugins install owner/repo --ref <sha>` (Git), or pip entry point `[project.entry-points."hermes_agent.plugins"]`. plugins.md [verified]
- A custom web-search provider plugin is also possible (`provides_web_providers`, RAW/website/docs/developer-guide/web-search-provider-plugin.md), but the provider result contract is the same `url/title/description` shape as section 1, so it cannot carry structured citations; a plugin tool can return any JSON. [verified for the contract in RAW/plugins/web/_common.py]

### Skills
- Format: a directory with `SKILL.md` ("Required: main instructions") plus optional `scripts/`, `references/`. Frontmatter: `name`, `description`, `version`, `author`, `license`, optional `platforms`, `metadata.hermes.{tags, related_skills, requires_toolsets, requires_tools, config, blueprint}`, `required_environment_variables`. `metadata.hermes.blueprint` (`schedule: "0 9 * * *"`, `deliver: origin`, `prompt`) "marks this skill a runnable automation". RAW/website/docs/developer-guide/creating-skills.md [verified]
- Locations: "All skills live in **`~/.hermes/skills/`**"; extra read locations via `skills.external_dirs` in `config.yaml`; project-local `<project-root>/.hermes/skills/` or `<project-root>/.agents/skills/` ("active only for sessions started inside that project"; project root = nearest ancestor with `.git`). Project skills are not auto-loaded: run `hermes skills trust` (stored in `skills.trusted_project_dirs`). Precedence `project → local (~/.hermes/skills/) → skills.create_dir → external_dirs`. RAW/website/docs/user-guide/features/skills.md [verified]
- Whether a gateway (Telegram) session picks up project-local skills is not stated in what was read [unknown]; `skills.external_dirs` pointing at the repo, or skills placed in `$HERMES_HOME/skills/`, do not depend on the launch directory.

### Repo-local config
- "A profile is a separate Hermes home directory. Each profile gets its own directory containing its own `config.yaml`, `.env`, `SOUL.md`, memories, sessions, skills, cron jobs, and state database." Named profiles live in `~/.hermes/profiles/<name>/`; select with `hermes -p <name> ...` / `hermes --profile=<name> ...`; create with `hermes profile create <name> [--clone|--clone-all]`; `hermes profile export coder` packs `coder.tar.gz` ("shareable; keys stripped"), `hermes profile import coder.tar.gz`. RAW/website/docs/user-guide/profiles.md [verified]
- "Profiles use the `HERMES_HOME` environment variable ... `HERMES_HOME` is the profile boundary. It controls Hermes config, `.env`, ..." and "`HERMES_HOME` selects user data" (installer flag `--hermes-home PATH`). So a repo-local directory works by exporting `HERMES_HOME=<repo>/<dir>`; plugins then live in `$HERMES_HOME/plugins/<name>/`. profiles.md, RAW/website/docs/getting-started/installation.md, RAW/website/docs/reference/cli-commands.md [verified]
- Caveat: "Don't point two agent processes at the same Hermes home directory." RAW/website/docs/user-guide/features/memory.md [verified]
- There is also a docs page `user-guide/profile-distributions.md` (not read) [unknown].

## 3. Hermes as a backend for our own UI

Docs list three protocols plus in-process Python. RAW/website/docs/developer-guide/programmatic-integration.md [verified]

| Interface | Transport | Docs' "best for" |
| - | - | - |
| ACP (`hermes acp`, `hermes-acp`) | JSON-RPC over stdio | IDE clients (VS Code, Zed, JetBrains) |
| TUI gateway | JSON-RPC over stdio (or WebSocket) | "Custom hosts that want fine-grained control of sessions, slash commands, approvals, and streaming events" |
| API server | HTTP + Server-Sent Events | "OpenAI-compatible frontends ... and language-agnostic web clients" |

- API server setup (in `~/.hermes/.env`): `API_SERVER_ENABLED=true`, `API_SERVER_KEY=...`, optional `API_SERVER_CORS_ORIGINS=http://localhost:3000` ("only if a browser must call Hermes directly"), `API_SERVER_HOST` (default `127.0.0.1`), `API_SERVER_PORT` (default `8642`). It starts with the gateway ("API server listening on http://127.0.0.1:8642"); auth is `Authorization: Bearer $API_SERVER_KEY`. RAW/website/docs/user-guide/features/api-server.md [verified]
- Endpoints: `POST /v1/chat/completions` (SSE streaming), `POST /v1/responses` (stateful), `POST /v1/runs` (returns run_id, 202), `GET /v1/runs/{id}`, `GET /v1/runs/{id}/events` (SSE), `POST /v1/runs/{id}/approval`, `POST /v1/runs/{id}/clarify`, `POST /v1/runs/{id}/steer`, `POST /v1/runs/{id}/stop`, `GET /v1/capabilities`, `GET /v1/models`, `GET /health`; plus Jobs API `/api/jobs` (cron CRUD + `/run`) and Sessions API `/api/sessions/*`. Headers `X-Hermes-Session-Id`, `X-Hermes-Session-Key`; `Idempotency-Key` supported. Same docs [verified]
- Approve/reject over HTTP: a gated tool call makes the run emit an `approval.request` event and park in `waiting_for_approval`; `GET /v1/runs/{run_id}` exposes `pending_controls`; answer with `POST /v1/runs/{run_id}/approval` body `{"request_id": "<prompt_id>", "execution_generation": 3, "choice": "once"}` (`once` runs, `deny` blocks). "MCP trust-gate consent — a write-capable tool on a server configured `trust: untrusted` — surfaces the same way". api-server.md [verified]
- `approvals.unattended_mode` default `deny` blocks dangerous commands instantly on `api_server`, with the exception "an api_server session whose client can answer the card (`/v1/runs` and streaming chat completions, via `POST /v1/runs/{id}/approval`) still gets the approval request." RAW/website/docs/user-guide/security.md [verified]
- Note: this approval gate is Hermes' dangerous-command / untrusted-MCP-write gate. It is not a general "approve this errand" primitive; the agent's `clarify` tool (answered via `POST /v1/runs/{id}/clarify`) is the documented way for the agent to ask the user a question. [verified for the endpoints; the mapping to an errand flow is a design inference]
- One-shot CLI: `hermes -z "<prompt>"` ("single prompt in, final response text out, nothing else on stdout or stderr"; `--usage-file` writes cost/tokens JSON); `hermes chat --oneshot -q "..."`; `hermes chat -q "..." --format stream-json` (structured JSONL); `hermes-agent --query "..."` minimal runner; `-t/--toolsets <csv>`, `--yolo`. RAW/website/docs/reference/cli-commands.md [verified]
- Python: `from run_agent import AIAgent`; `agent.chat("...")`, `agent.run_conversation(...)`; docs include a FastAPI example. Install is `git clone` + `source ./activate`; "Hermes does not publish a supported wheel or source distribution for `requirements.txt` installs." RAW/website/docs/guides/python-library.md [verified]
- Webhooks: `hermes webhook subscribe|list|remove|test` for "event-driven activation" (inbound HTTP triggers; details in user-guide/messaging/webhooks.md, not read in depth). cli-commands.md [verified for existence]
- Webapp (v0.23.0): "Hermes Desktop in a browser", served by the gateway. Config `webapp: {enabled: false, host: 127.0.0.1, port: 9120, public_url: ""}`; open with `hermes webapp` (`--status`, `--no-open`). Public exposure: `host: 0.0.0.0`/`::` or `public_url` set turns on sign-in and "requires a dashboard sign-in provider" (username/password provider, e.g. `HERMES_DASHBOARD_BASIC_AUTH_PASSWORD`, or Nous OAuth); "the listener refuses to start without one"; behind a tunnel also set `dashboard.trusted_proxies`. It is the full Hermes workspace UI, not a page you design. RAW/website/docs/user-guide/configuration.md (Webapp), RAW/website/docs/user-guide/docker.md [verified]
- Dashboard: `hermes dashboard` on `http://127.0.0.1:9119` (`--host`, `--port`, `--no-open`); a public bind "always requires an auth provider". RAW/website/docs/user-guide/features/web-dashboard.md [verified]
- Least-effort route for a custom page, per the docs' own selector ("You want any OpenAI-compatible frontend, a language-agnostic HTTP client, or curl-driven automation → API server"): a small page or thin proxy that calls `POST /v1/runs`, listens on `GET /v1/runs/{id}/events`, and posts to `/v1/runs/{id}/approval` or `/clarify`. Keep `API_SERVER_KEY` server-side (the browser-direct option needs `API_SERVER_CORS_ORIGINS`).

## 4. Hermes messaging details (Telegram)

- Sessions: Telegram DM key `agent:main:telegram:dm:<chat_id>` ("One session per DM chat"); group `agent:main:<platform>:group:<chat_id>:<user_id>` ("Per-user inside the group"), default `group_sessions_per_user: true`; group topics are shared unless `thread_sessions_per_user: true`. RAW/website/docs/user-guide/sessions.md [verified]
- Memory is NOT per Telegram user: "Memory is per [profile]: `hermes -p work` ... reads `~/.hermes/profiles/work/memories/`", files `memories/MEMORY.md` (2,200 chars) and `memories/USER.md` (1,375 chars). All users of one bot/profile share them. RAW/website/docs/user-guide/features/memory.md [verified]
- Cross-user leak to know about: "`session_search` reads the whole session store of the profile it runs in: every chat, from every platform and every user in that profile's allowlist. On a shared or family bot, anyone allowed to talk to it can ask the agent to find and read anyone else's conversations with it." sessions.md [verified]. Per-user isolation therefore means one profile (and one bot token) per user; "Different bot tokens" per profile is the documented pattern (profiles.md).
- Approvals in chat: `/approve` and `/deny` commands; security.md describes an "approval card" that members answer "with a button, reaction or bare \"yes\"", and that a non-approver's click gets "a Telegram callback alert" (i.e. inline buttons on Telegram). `destructive_slash_confirm` uses "native yes/no buttons on Telegram, Discord, and Slack". The `clarify` tool renders choices as "a numbered prompt (or native buttons on platforms that support them)". RAW/website/docs/user-guide/security.md, RAW/website/docs/user-guide/messaging/index.md [verified]; the Telegram page itself does not describe the approval UI.
- Sending files/images: "The gateway extracts `MEDIA:/path/to/file` tags from agent replies and ships the referenced file as a platform-native attachment"; with a Docker terminal backend the path must be host-visible. Add `[[as_document]]` to avoid lossy image compression. RAW/website/docs/user-guide/messaging/telegram.md, creating-skills.md [verified]
- Incoming voice: "Voice messages you send on Telegram are automatically transcribed by Hermes's configured STT provider and injected as text". Config `stt.provider: "local" | "groq" | "openai" | "mistral" | "xai" | "elevenlabs" | "deepinfra"`; default Local Whisper (faster-whisper, no key), Groq `GROQ_API_KEY`, OpenAI `VOICE_TOOLS_OPENAI_KEY` or `OPENAI_API_KEY`. `stt.enabled: false` hands the agent the audio file path instead. Telegram public Bot API caps downloads at 20 MB. RAW/website/docs/user-guide/features/tts.md, telegram.md [verified]
- TTS, ElevenLabs is native: `tts.provider: "elevenlabs"` with `ELEVENLABS_API_KEY`, `tts.elevenlabs.voice_id: "pNInz6obpgDQGcFmaJgB"` (Adam), `tts.elevenlabs.model_id: "eleven_multilingual_v2"`. Full provider list: `"edge"` (default, free) | `"elevenlabs"` | `"openai"` | `"minimax"` | `"mistral"` | `"gemini"` | `"xai"` | `"deepinfra"` | `"neutts"` | `"kittentts"` | `"piper"`. "OpenAI, ElevenLabs, and Mistral produce Opus natively", so Telegram voice bubbles need no ffmpeg. With ElevenLabs the `text_to_speech` tool accepts a per-call `voice_id` and can search the Voice Library; "The ElevenLabs API key needs the **Text to Speech** permission to speak and **Voices: Read** to search." ElevenLabs STT also exists (`stt.provider: elevenlabs`; realtime "Scribe v2 realtime"). Python extra: `tts-premium = ["elevenlabs==1.59.0"]`. tts.md, RAW/website/docs/user-guide/features/voice-mode.md, RAW/pyproject.toml [verified]
- Cron delivery: `deliver:` values `"origin"` ("Back to where the job was created", default on messaging platforms), `"telegram"` (home channel, `TELEGRAM_HOME_CHANNEL`), `"telegram:123456"` (specific chat), `"telegram:-100123:17585"` (topic), `"all"`. "The agent's final response is automatically delivered to the configured `deliver:` target — the agent does not send messages itself". CLI `--deliver telegram`. `cron.mirror_delivery: true` makes deliveries continuable in the chat session. `hermes send` sends a one-shot message with no agent loop. RAW/website/docs/user-guide/features/cron.md, cli-commands.md [verified]
- Access: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_USERS` (comma-separated ids); polling by default, webhook mode needs `TELEGRAM_WEBHOOK_URL` + `TELEGRAM_WEBHOOK_SECRET`. telegram.md [verified]

### /search request and response (https://exa.ai/docs/reference/search.md) [verified]
- `type`: `auto` (default, ~1 s), `lite` (~300 ms), `deep-lite`, `deep`; legacy `instant`, `fast`, `deep-reasoning`. `numResults` 1 to 100, default 10; no pagination.
- `contents.text` (bool or `{maxCharacters}`), `contents.highlights` (bool or `{query, verbosity}`), `contents.summary` (`{query, schema}`), plus `maxAgeHours`, `livecrawl`, `subpages`, `extras`.
- `category`: `company`, `publication`, `news`, `personal site`, `financial report`, `people`. Filters: `startPublishedDate`, `endPublishedDate`, `includeDomains`, `excludeDomains`, `userLocation`, `additionalQueries`, `systemPrompt`.
- Structured output: `outputSchema` "Works with every search type except `lite` and adds about 2 seconds"; "Object schemas are limited to 10 properties in total ... and 2 levels of nesting". Synthesised output returns `output.content` + `output.grounding[]` = `{field, citations: [{url, title}], confidence: low|medium|high}`.
- Per-result fields: `title`, `url`, `publishedDate`, `author`, `id`, `image`, `favicon`, `text`, `highlights` (string array), `summary`, `subpages`, `entities`, `extras`. No `highlightScores` or `score` in the current reference. Top level includes `costDollars` (e.g. `{"total": 0.007}`).
- `lite` rejects `outputSchema`, `systemPrompt`, `stream`, `additionalQueries`, `contents.summary` and serves cache only.
- `/answer`: returns `answer` + `citations[]` (`title`, `url`, `publishedDate`, `author`, `id`, `image`); accepts `outputSchema`, `stream`. https://exa.ai/docs/reference/answer.md [verified]
