# UKK on the Web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `/ukk` page on the production site where a visitor chats with the same UKK, served by a second, web-only Hermes instance with memory and reminders off.

**Architecture:** The existing Hermes image gains a web runtime mode (no Telegram, API server on, memory and cronjob tools disabled). Compose runs it as `hermes-web`, reachable only on the Compose network. The Next.js site proxies `/api/ukk` to its OpenAI-compatible streaming endpoint, holding the key server-side and keeping each visitor's Hermes session in an HMAC-signed cookie. The page streams replies.

**Tech Stack:** Hermes (pinned) API server, Docker Compose, Python 3 `unittest`, Bash, Next.js App Router + TypeScript, Vitest, Zod.

**Spec:** `docs/superpowers/specs/2026-11-14-ukk-web-design.md`

## Global Constraints

- Telegram and the web page are the only channels.
- `hermes-web` never holds `TELEGRAM_BOT_TOKEN`; its port 8642 is never published to the host.
- On the web instance the `memory` and `cronjob` toolsets are disabled and `api_server.max_concurrent_runs` is `4`.
- The API key (`UKK_API_KEY` on the site, `API_SERVER_KEY` in `hermes-web`) never reaches the browser.
- `/api/ukk` requires the demo code (`mayResearch` in `src/lib/cases.ts`) and `allow()` from `src/lib/rate-limit.ts`; messages are at most 1,500 characters.
- Without `UKK_API_URL`/`UKK_API_KEY` (Vercel), `/ukk` links to `NEXT_PUBLIC_UKK_CHAT_URL`, default `https://86.38.238.136.sslip.io/ukk`, instead of failing.
- The Telegram bot's behaviour and existing Compose modes are unchanged.
- Copy: "Research with sources, not legal advice." and "UKK is a made-up character, not an official service." appear on `/ukk`. Never "100% accurate".
- Commits: imperative subject, at most 72 characters, no model names or secrets; decisions in `docs/DECISIONS.md` with a Helsinki timestamp.

## Review Focus

1. A visitor edits the session cookie to another visitor's Hermes session ID (they may be guessable timestamps): the route must ignore any cookie it did not sign. Pinned in Task 3.
2. Hermes or the network fails mid-stream: the visitor sees one plain error line, not a hung spinner or a stack trace. Pinned in Task 3 (upstream error) and Task 4 (stream parser).
3. A first-time visitor without the demo code opens `/ukk` directly: one sentence telling them to scan the QR code, no request sent. Pinned in Task 4.
4. Many visitors at once: the fifth concurrent run gets Hermes's 429, which the route turns into "UKK is busy, try again in a minute." Pinned in Task 3.
5. A deploy where `hermes-web` fails to start: the release rolls back. Pinned in Task 2 by the deploy check.

### Task 3: `/api/ukk`

**Files:**
- Create: `src/lib/ukk.ts`, `src/app/api/ukk/route.ts`, `tests/ukk.test.ts`

**Interfaces:**
- Produces: `ukkConfigured(): boolean`; `signSession(id: string): string`; `readSession(cookie: string | undefined): string | null` (HMAC-SHA256 with `UKK_API_KEY`, `id.signature`, constant-time compare); `POST /api/ukk` with JSON `{ message: string }` → `text/event-stream` of Hermes's OpenAI chunks, or JSON `{ error }` with 400, 401, 429, 502, 503 (503 body also has `chatUrl`). Cookie `ukk_session`: httpOnly, SameSite=Lax, `Secure` in production, Path `/api/ukk`, Max-Age 86400.

- [ ] **Step 1: Failing tests** in `tests/ukk.test.ts` (stub `fetch` and env as `tests/security.test.ts` does):
  - 401 without `x-demo-code`;
  - 400 for an empty message or one of 1,501 characters;
  - 503 with `chatUrl` when `UKK_API_URL` is unset;
  - a valid request calls `${UKK_API_URL}/v1/chat/completions` with `Authorization: Bearer <key>`, `stream: true` and the message as the only user message;
  - the upstream `X-Hermes-Session-Id` comes back as a signed `ukk_session` cookie;
  - a validly signed cookie is forwarded as `X-Hermes-Session-Id`;
  - a tampered or unsigned cookie is not forwarded;
  - upstream 429 → 429 with "UKK is busy, try again in a minute.";
  - upstream 500 → 502 with a generic message;
  - the response body and headers never contain the key.
